## Private SVG release checklist

Each box stays open until its owner attaches evidence for the selected archive. Keep private evidence with the handoff. Record the date, source revision, archive SHA-256, runtime versions, profile settings, tester, result, and evidence location. A failed required check keeps distribution on hold.

- [ ] **Engineering — freeze the package.** For an existing handoff, verify the retained bytes. For a new candidate, follow the [private archive procedure](../README.md#build-a-private-release-archive). Inspect the file list from `tar -tzf "$release_dir/$package_file"` for the intended payload and absence of external binaries or caches. Install from that archive in an empty prefix with `--omit=dev --omit=optional`. Keep the checksum, install result, installed SBOM, and notices together. Identify the approved registry or populated cache the second Mac will use to install the locked npm dependencies. [npm SBOM](https://docs.npmjs.com/cli/v11/commands/npm-sbom/)
- [ ] **Security and distribution owner — clear the selected environment.** Review the installed dependency advisories, the provisioned Node and playback browser, and any accepted exceptions with an owner and review date. Reconcile notices with the installed SBOM and obtain project distribution terms for the private handoff. The earlier license inventory covers a planning candidate. [Commercial license audit](v1.1-commercial-license-audit.md#7-verification-and-freeze-criteria)
- [ ] **IT — install on a second macOS ARM64 workstation.** Check the received digest before installation. Point Codex at the installed executable with `ANIMATION_MCP_VIDEO_FORMATS=none`, `ANIMATION_MCP_ENABLE_3D=false`, and an approved absolute `ANIMATION_MCP_OUTPUT_DIR`. Reconnect. Confirm the three SVG tools above, one successful export under that root, and rejection of video calls. Record the OS, Node, npm, Codex, browser, and actual client timeout.
- [ ] **Pilot user and workflow owner — accept the result.** Use an approved internal or synthetic brief. Describe the workflow in Codex, preview a meaningful midpoint, request one correction, export, and locate the file. Open it directly in the designated browser with networking disabled. Verify labels, ordering, position and opacity, final hold, and replay after reload. Record assistance needed and the user's acceptance of the corrected result.
- [ ] **Engineering and IT — rehearse failure and recovery.** Use a disposable root. Exercise an invalid scene, the largest planned workload, an unwritable or obstructed output path, and an interrupted export. Record elapsed time, available disk space, errors, residual files, and a successful retry. Reconnect after process exit. Check stdout contains only MCP messages and diagnostics use stderr. [MCP stdio specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#stdio)
- [ ] **IT and support — rehearse rollback and retention.** Record the approved output location, allowed data, access, retention period, and support contact. Save the previous registration and its matching archive or prefix. Disable the new entry and reconnect. If there is an approved previous installation, restore its registration, verify discovery, and export a sample. For a first install verify the disabled tools disappear. Reopen a saved SVG offline after rollback. Each successful retry creates a new directory. Review interrupted-job leftovers under the configured root before applying retention.
- [ ] **Pilot owner — record go or hold.** Identify participants, permitted data in the Codex conversation, the approved archive and deployment profile, open issues, and who can stop distribution. Confirm every applicable gate in the [pilot criteria](singapore-macos-arm64-pilot.md#release-acceptance). Record the decision, name, and date before sharing the package. Reopen affected gates when the archive, runtime, browser, audience, or delivery profile changes.
